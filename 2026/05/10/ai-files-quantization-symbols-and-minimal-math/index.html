量化：符号与最小数学地图

这页不是数学考试，而是读量化教程和论文时随手查的地图。量化公式大多在回答三件事：

初学者先抓住

看到公式时先问：这个符号是权重、激活还是 KV cache；scale 是一整层共用还是每组共用；误差是在单个数上看，还是在矩阵乘输出上看。

1. 最常见的量化公式

q=clip(round(xs)+z, qmin⁡, qmax⁡)q = \mathrm{clip}\left(\mathrm{round}\left(\frac{x}{s}\right)+z,\ q_{\min},\ q_{\max}\right) q=clip(round(sx​)+z, qmin​, qmax​)

x^=s(q−z)\hat{x}=s(q-z) x^=s(q−z)

符号 读法 含义
xxx original value 原始浮点值，可以是权重、激活或 cache 元素
qqq quantized value 低比特整数值
x^\hat{x}x^ reconstructed value 反量化后的近似浮点值
sss scale 一个整数格子对应多大的真实数值间隔
zzz zero-point 让真实 0 对齐到整数范围的偏移
qmin⁡,qmax⁡q_{\min}, q_{\max}qmin​,qmax​ quantized range 当前 bit 数能表示的最小和最大整数
round\mathrm{round}round rounding 四舍五入或其它舍入策略
clip\mathrm{clip}clip clipping 超出范围时截断到可表示边界

读作什么：把 xxx 除以 scale，变成“第几个格子”；加上 zero-point 后得到整数；如果整数超过低比特范围，就裁到边界；计算时再把整数还原成近似浮点值 x^\hat{x}x^。

小例子：若 s=0.5,z=0s=0.5,z=0s=0.5,z=0，则 x=1.2x=1.2x=1.2 先变成 1.2/0.5=2.41.2/0.5=2.41.2/0.5=2.4，round 后 q=2q=2q=2，反量化 x^=0.5×2=1.0\hat{x}=0.5\times2=1.0x^=0.5×2=1.0。误差是 0.20.20.2。

常见误解

qqq 不是模型真正想要的输出，它只是低比特存储或低比特计算中的中间表示。模型质量最终看的是 x^\hat{x}x^ 进入矩阵乘、attention 和后续层以后，输出是否仍然接近原模型。

2. bit 数和整数范围

如果使用 bbb bit，有符号整数通常能表示：

qmin⁡=−2b−1,qmax⁡=2b−1−1q_{\min}=-2^{b-1},\qquad q_{\max}=2^{b-1}-1 qmin​=−2b−1,qmax​=2b−1−1

符号 含义 例子
bbb bitwidth，每个量化值用多少 bit INT8 的 b=8b=8b=8，INT4 的 b=4b=4b=4
qmin⁡q_{\min}qmin​ 最小整数 INT4 常为 −8-8−8
qmax⁡q_{\max}qmax​ 最大整数 INT4 常为 777

读作什么：bit 越少，可用格子越少。INT8 大约有 256 个格子，INT4 只有 16 个格子。格子少不一定不能用，但 scale 和 outlier 会变得更关键。

格式 有符号整数范围 直觉
INT8 [−128,127][-128,127][−128,127] 格子较多，激活量化更常见
INT4 [−8,7][-8,7][−8,7] 压缩强，常用于 weight-only
INT2 [−2,1][-2,1][−2,1] 极激进，通常需要特殊训练或强保护

3. scale 怎么选

最简单的对称量化会用最大绝对值决定 scale：

s=max⁡(∣x∣)qmax⁡s=\frac{\max(|x|)}{q_{\max}} s=qmax​max(∣x∣)​

符号 含义
$\max( x
qmax⁡q_{\max}qmax​ 正向最大可表示整数
sss 每一格代表的真实间距

读作什么：最大的数要刚好放进最大整数格子里，因此 scale 等于“最大真实值 / 最大整数值”。

离群值例子：一组激活大多在 [−2,2][-2,2][−2,2]，但有一个值是 303030。INT4 的 qmax⁡=7q_{\max}=7qmax​=7，scale 会变成 30/7≈4.2930/7\approx4.2930/7≈4.29。这时 −2-2−2 到 222 的主体区域只有一两个格子可用，细节几乎被抹掉。

为什么 activation outlier 麻烦

权重是固定的，可以离线分析；激活随每个输入变化。一个少见 token、长上下文位置或图像局部细节，都可能让某层 activation 突然出现大值，迫使 scale 变粗。

4. 对称和非对称量化

对称量化常写成：

q=round(xs),x^=sqq=\mathrm{round}\left(\frac{x}{s}\right),\qquad \hat{x}=sq q=round(sx​),x^=sq

非对称量化常写成：

q=round(xs)+z,x^=s(q−z)q=\mathrm{round}\left(\frac{x}{s}\right)+z,\qquad \hat{x}=s(q-z) q=round(sx​)+z,x^=s(q−z)

名称 适合什么分布 代价
对称量化 数值大致围绕 0 简单，kernel 更友好
非对称量化 数值明显偏正或偏负 zero-point 处理更复杂

读作什么：如果数据天然围绕 0，对称量化够用；如果数据整体偏移，zero-point 可以让整数范围利用得更充分。

5. 量化粒度：一个 scale 管多大

设一个激活矩阵：

X∈RB×T×dX\in\mathbb{R}^{B\times T\times d} X∈RB×T×d

符号 含义
BBB batch size，一次处理多少条样本
TTT sequence length，token 数或时间步数
ddd hidden dimension，每个 token 的向量维度
XXX activation tensor，某层输入或输出激活

不同量化粒度的区别，是 scale 覆盖的范围不同：

粒度 scale 形状直觉 优点 风险
per-tensor 整个 XXX 一个 scale 元数据最少，简单 一个 outlier 影响所有值
per-token 每个 token 一个 scale 适合动态激活 在线统计和 kernel 更复杂
per-channel 每个 hidden channel 一个 scale 能保护通道差异 scale 读取更多
group-wise 每组通道或 token 一个 scale 精度和成本折中 group size 要和 kernel 匹配
per-element 每个元素一个 scale 误差最小 元数据通常太贵
实用判断

scale 越细，误差通常越小；但 scale 本身也要存、要读、要参与 dequant。量化收益不是只看 qqq 变小，也要看 scale 和 dequant 是否拖慢热路径。

6. 线性层里误差看什么

原始线性层：

Y=XWY=XW Y=XW

量化后近似为：

Y^=X^W^\hat{Y}=\hat{X}\hat{W} Y^=X^W^

误差可以粗略写成：

ΔY=Y−Y^\Delta Y = Y-\hat{Y} ΔY=Y−Y^

符号 含义 常见 shape
XXX 输入激活 B×T×dinB\times T\times d_{\text{in}}B×T×din​
WWW 权重矩阵 din×doutd_{\text{in}}\times d_{\text{out}}din​×dout​
YYY 原始输出 B×T×doutB\times T\times d_{\text{out}}B×T×dout​
X^\hat{X}X^ 量化再反量化后的激活 同 XXX
W^\hat{W}W^ 量化再反量化后的权重 同 WWW
ΔY\Delta YΔY 输出误差 同 YYY

读作什么：真正重要的不是每个权重是否近似，而是量化后的矩阵乘输出是否仍然接近原输出。GPTQ、AWQ 和 SmoothQuant 都是在用不同方式控制这个输出误差。

7. GPTQ 里的二阶直觉

GPTQ 常用下面的目标来描述一层权重量化：

min⁡W^ ∥WX−W^X∥22\min_{\hat{W}}\ \|WX-\hat{W}X\|_2^2 W^min​ ∥WX−W^X∥22​

符号 含义
WWW 原始权重
W^\hat{W}W^ 量化后的权重近似
XXX 校准集激活，用来代表真实输入分布
∥⋅∥22\|\cdot\|_2^2∥⋅∥22​ 平方误差

读作什么：不要只让 W^\hat{W}W^ 像 WWW，而是让它们乘上真实激活 XXX 以后输出尽量像。Hessian 或近似二阶信息用来判断哪些方向更敏感。

初学者够用理解

二阶信息不是神秘魔法。它大致是在说：同样大小的权重误差，落在不同方向上，对输出和 loss 的伤害不同。GPTQ 尝试在量化一部分权重后，补偿剩余权重，减少输出变化。

8. AWQ 里的激活敏感通道

AWQ 的核心直觉可以写成：

Y=∑iXiWiY=\sum_i X_i W_i Y=i∑​Xi​Wi​

符号 含义
iii 输入通道或 hidden 维索引
XiX_iXi​ 第 iii 个通道的激活
WiW_iWi​ 第 iii 个通道对应的权重
XiWiX_iW_iXi​Wi​ 这个通道对输出的贡献

读作什么：有些权重本身看起来不大，但它所在通道的激活经常很大，最终对输出很重要。AWQ 用校准激活找这些通道，并在量化前给它们更好的保护。

9. SmoothQuant 的重参数化

线性层输出可以写成：

Y=XWY=XW Y=XW

SmoothQuant 使用一个可合并的对角缩放矩阵 DDD：

Y=(XD−1)(DW)Y=(XD^{-1})(DW) Y=(XD−1)(DW)

符号 含义
DDD 对角缩放矩阵，每个通道一个缩放因子
XD−1XD^{-1}XD−1 被平滑后的激活
DWDWDW 承接缩放后的权重

读作什么：输出没有变，但难量化的 activation outlier 被压平了一部分；代价转移到更容易离线处理的权重上。

直觉例子：搬家时不是把所有箱子都变轻，而是把最难搬、最容易挡路的箱子重新分配到更好处理的位置。

10. LoRA 和 QLoRA 的符号

LoRA 把权重更新写成：

W′=W+ΔW,ΔW=BAW' = W+\Delta W,\qquad \Delta W=BA W′=W+ΔW,ΔW=BA

符号 含义 常见 shape
WWW 冻结的原始权重 dout×dind_{\text{out}}\times d_{\text{in}}dout​×din​
W′W'W′ 适配后的有效权重 同 WWW
ΔW\Delta WΔW LoRA 训练出来的低秩增量 同 WWW
AAA 降维矩阵 r×dinr\times d_{\text{in}}r×din​
BBB 升维矩阵 dout×rd_{\text{out}}\times rdout​×r
rrr rank，低秩瓶颈维度 远小于 din,doutd_{\text{in}},d_{\text{out}}din​,dout​

QLoRA 的关键是：

Wbase≈W^4bit,W′=W^4bit+BAW_{\text{base}}\approx \hat{W}_{\text{4bit}},\qquad W'= \hat{W}_{\text{4bit}} + BA Wbase​≈W^4bit​,W′=W^4bit​+BA

读作什么：底座权重用 4bit 存储并冻结，训练时只更新小的 LoRA adapter。它主要省微调显存，不等于所有计算都在 4bit 里完成。

11. KV cache 显存公式

自回归生成中，每层都要缓存历史 token 的 Key 和 Value。一个常见估算：

KV Memory≈2×L×B×T×Hkv×dh×bytes\mathrm{KV\ Memory}\approx 2 \times L \times B \times T \times H_{\text{kv}} \times d_h \times \mathrm{bytes} KV Memory≈2×L×B×T×Hkv​×dh​×bytes

符号 含义
222 Key 和 Value 两份缓存
LLL Transformer 层数
BBB batch size 或并发序列数
TTT 上下文长度
HkvH_{\text{kv}}Hkv​ KV head 数，GQA/MQA 下可小于 query head 数
dhd_hdh​ 每个 head 的维度
bytes\mathrm{bytes}bytes 每个元素占多少字节，BF16 为 2，INT8 为 1

读作什么：KV cache 随层数、并发、上下文长度、KV head 数和 dtype 线性增长。把 BF16 KV 改成 INT8，理论上 bytes 减半，但还要看 scale、dequant 和长程质量。

小账：若 L=32,B=8,T=16384,Hkvdh=4096,bytes=2L=32,B=8,T=16384,H_{\text{kv}}d_h=4096,\mathrm{bytes}=2L=32,B=8,T=16384,Hkv​dh​=4096,bytes=2，则 KV 本体约：

2×32×8×16384×4096×2≈64GiB2\times32\times8\times16384\times4096\times2\approx64\mathrm{GiB} 2×32×8×16384×4096×2≈64GiB

这解释了为什么长上下文服务里，权重已经 4bit 后，显存仍可能被 KV cache 吃满。

12. 读量化公式的四句检查

  1. 这个公式量化的是 WWW、XXX、K/VK/VK/V，还是训练状态？
  2. scale 是 per-tensor、per-channel、per-token，还是 group-wise？
  3. 误差是在单个数上看，还是在 XWXWXW、attention 或最终任务上看？
  4. 低比特路径是否真的由目标 runtime 和 kernel 执行？

如果这四句答不清，先不要比较哪个方法更强。量化里最容易迷路的地方，就是把数值格式、误差控制算法和系统执行路径混成一件事。
